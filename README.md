# 基于图纸的大模型自动生成 CNC G 代码 —— 技术可行性 PoC

> 载体：阶梯轴（φ20-φ30-φ40，总长 110，45 钢）
> 系统：FANUC 0i-TF / GSK 980TDc 通用
> 日期：2026-10-28

---

## 0. 结论先行

把「能不能做」拆成三层问，答案完全不同：

| 层次 | 判断 | 依据 |
|---|---|---|
| **技术可行**：能否从图纸自动提取特征并生成语法正确、几何自洽的 G 代码 | **可行（约 70%）** | 阶梯轴这类回转体是最容易的一档：特征是显式的（外圆/端面/倒角/槽），尺寸链闭合，没有自由曲面。本 PoC 已跑通全链路 |
| **工程可行**：能否稳定做到「人看一眼就敢按循环启动」 | **勉强（约 55%）** | 卡在三个非图纸信息：毛坯、装夹、刀补表。这三样任何一样给错，代码再漂亮也会撞刀 |
| **生产可行**：无人复核直接下发车间 | **不可行（0%）** | 大模型会「编」坐标 —— 它能写出格式完全正确、但几何自相矛盾的程序，而且写得非常有信心 |

**一句话：这条路值得投，但产品形态必须是「LLM 出草稿 + 规则校验 + 仿真 + 人工签核」，不是「LLM 出程序」。**

## 2. 零件与工艺基线

### 2.1 几何

| 段 | 直径 | Z 范围 | 长度 | 说明 |
|---|---|---|---|---|
| ① | φ20 | 0 ~ −30 | 30 | 自由端，端面 C3 倒角 |
| ② | φ30 | −30 ~ −60 | 30 | 台阶处 C3 倒角 |
| ③ | φ40 | −60 ~ −87 | 27 | 台阶处 C3 倒角 |
| ④ | φ36 | −87 ~ −90 | 3 | 退刀槽（磨削/螺纹越程） |
| ⑤ | φ45 | −90 ~ −110 | 20 | 毛坯原面，卡盘夹持区，不加工 |
| 槽 | φ16 | −18 ~ −21 | 3 | 切槽，槽底 R 自然形成 |

**9 个加工特征**：端面 1 + 外圆 3 + 3×45° 倒角 3 + 切槽 1 + 退刀槽 1。

### 2.2 工装与刀具

- 毛坯 φ45×130，45 钢，卡盘夹持 φ45 段 20，右端悬伸 110（长径比 2.4，**不需尾座**）
- T0101 粗车 CNMG120408 R0.8，主偏角 95°
- T0202 精车 VNMG160404 R0.4，刀尖方位号 **T3**
- T0303 切槽，刀宽 3 mm，左刀尖对刀

### 2.3 切削参数

| 工序 | 线速度 | 进给 | 切深 |
|---|---|---|---|
| 粗车 | G96 S150（φ45 处 1061 r/min） | f 0.25 mm/r | ap 2.25 mm（直径 4.5） |
| 精车 | G96 S200 | f 0.12 mm/r | ap 0.25 mm（直径 0.5） |
| 切槽 | G97 S800 | f 0.06 mm/r | 一次切入 |

粗车留 **0.5 mm 直径余量**（0.25 径向），台阶端面留 0.2 轴向余量 —— 这一点在初稿里我写错了（粗车直接切到 φ40，精车没有余量），是本次 PoC 里最典型的一类错误，见 §5。

## 3. 端到端管道：LLM 在哪里，不在哪里

```
图纸(PDF/DWG)          人工/OCR           LLM                规则引擎
     │                    │                │                    │
  [1] 尺寸与公差提取 ──────┤                │                    │
     │                    │                │                    │
  [2] 特征图(Feature Graph) ────────────────┤                    │
     │                                     │                    │
  [3] 工艺规划(工序/刀具/切削参数) ─────────┤                    │
     │                                     │                    │
  [4] G 代码生成 ──────────────────────────┤                    │
     │                                     │                    │
  [5] 校验 ────────────────────────────────┼──── 几何/语法/碰撞 ─┤
     │                                     │                    │
  [6] 仿真 + 人工签核 ◄─────────────────────┴────────────────────┘
```

各段的人机分工：

| 段 | LLM 能做 | 必须人来定 |
|---|---|---|
| [1] 尺寸提取 | 识别图框、标题栏、技术要求、粗糙度符号；把尺寸链转成结构化 JSON | 图纸模糊/缺尺寸/多义时的裁量 |
| [2] 特征图 | 把「φ20 / Z 0~−30 / 两端倒角」组织成加工特征树 | **毛坯尺寸、装夹方式、基准面**（图上根本没有） |
| [3] 工艺规划 | 按材料+特征查表给工序顺序、刀具、vc/f/ap | 车间实际有什么刀片、机床刚性、冷却方式 |
| [4] 代码生成 | 模板化输出，行号、注释、模态指令管理 | **刀补表内容**（R 与刀尖方位号）、对刀点 |
| [5] 校验 | 写规则脚本（本例 `03_toolpath.py` 就是最朴素的一种） | 判定「这个刀路合不合理」 |
| [6] 签核 | — | **只有人能签** |

## 4. 真正难的不是生成，是「图纸是欠定的」

一张 2D 工程图对车削来说，**信息量不足以唯一确定加工程序**。至少缺三样：

1. **毛坯**：图只写成品 φ20/30/40，没写从 φ45 还是 φ50 棒料来。余量不同，走刀次数就不同。
2. **装夹**：夹哪一段、夹多长、要不要尾座、要不要中心架 —— 决定有没有「让刀」和振纹风险。
3. **刀补表**：`G42` 只告诉系统「按刀尖圆弧补偿」，补多少靠机床里的 R 和刀尖方位号。图上一个字都没有。

**结论：这三样必须是结构化输入，不能靠 LLM 猜。** 猜出来的程序能跑，但余量错一刀、退刀少 0.5 mm，就是废件或者撞刀。

## 5. G 代码生成的质量边界（本次实测）

### 5.1 LLM 做得好的

- **格式与模态管理**：G40/G97/G99 程序头复位、G96 与 G50 S 的配合、G04 暂停、M08/M09 顺序、M30 收尾 —— 这些是强模板，几乎不出错。
- **注释密度**：每行一句工艺说明（本例 60+ 行代码全注释），这是人工写程序最容易偷懒的地方。
- **变体生成**：同一零件要 Fanuc 版 / 广数版 / 带 G71 循环版，改写成本极低。

### 5.2 LLM 反复会错的（本例实际发生 2 处）

| # | 错误 | 后果 | 这类错误的特征 |
|---|---|---|---|
| 1 | 粗车直接切到 φ40，精车没有余量 | 精车刀空走一刀，尺寸靠粗车保证，Ra 不合格 | **几何自洽但工艺不自洽** —— 单看代码没错，看工艺才错 |
| 2 | 切槽刀从 X47 一路 `G01` 进给到 X16 | 15 mm 空走刀，单件多耗 3~5 s，批量后是钱；且进给切入的起始点不受控 | **合法但不合理** —— 语法通过，工艺习惯缺失 |

两处都是我以「15 年工艺」视角改的，**规则引擎拦不住第 1 类，仿真也拦不住第 2 类**。这就是为什么必须有人。

### 5.3 一个具体的坑：G50 是双义的

```
G50 X260.0 Z280.0   ← 工件坐标系设定
G50 S2000           ← 恒线速最高转速钳位
```

同一个 G50，带 X/Z 和带 S 是两件事。而 `G92` 在 Fanuc 与 GSK980TD 上是**螺纹切削循环**，部分老系统却拿它当坐标系设定 —— 两者混用，轻则程序报警，重则螺纹循环在空行程里启动直接撞卡盘。**本例统一用 G50，并在程序头注明。**

## 6. 给现场高工的三条审核红线 ★

### ① 安全对刀点与退刀距离

- 每刀径向退到 `X47`，距毛坯 φ45 只有 **1 mm 余隙**。若毛坯椭圆度超 0.5 mm，或刀尖 Z 向对偏，第一刀就会蹭伤。**首件建议先改 `X48` 空跑一遍**。
- `G50 X260 Z280` 要求刀尖**物理上就在参考点**。对刀完成后必须重新执行一次 G50，否则整个坐标系是平移错的 —— 这类错误表现为「所有尺寸系统性偏大/偏小一个固定值」。
- 首件三件套：**单段运行（SINGLE BLOCK）+ 进给倍率 25% + 快速倍率 25%**，手不离进给保持。

### ② 进给量与转速的匹配

- 恒线速在 φ20 处理论转速 3183 r/min，被 `G50 S2000` 钳到 2000，**实际线速度只有 126 m/min**。这不是错误，但排产核算节拍时要按 2000 的上限算，不能按 200 算。
- 切槽 `f0.06` 是为断屑。**材料若从不锈钢换成 45 钢以外的高塑性料，要降到 0.04 并开内冷**，否则缠屑拉伤槽壁。
- 粗车 `ap 2.25` 对应 CNMG 的槽型能力上限附近，**机床刚性不足（旧机、刀杆悬伸 > 4D）时应降到 1.5**。

### ③ 防撞刀的人工复核红线

- **刀补表**：`R0.4` + 刀尖方位号 `T3` 必须与 T0202 实际刀片完全一致。R 填错（0.4 写成 0.8），3×45° 倒角会**直接过切 0.4 mm**，台阶根部还会留 0.4 mm 凸台 —— 这两种缺陷都不会报警，只会废件。
- **G42 引入段长度**：N390 的位移为 ΔX 6 mm、ΔZ 4 mm（合成 7.2 mm），必须 **≥ 2×R**。引入段改短会导致补偿建立不完全，切入点啃刀。
- **逐段核对每一处 `G00` 的 Z 向移动**：本例有 5 处 `G00 Z3.0` 和 2 处 `G00 Z-19.5 / Z-88.5`，必须确认执行瞬间的 X 位置高于该处最大直径 + 2 mm。
- 上机前 **三件缺一不可**：CAM 仿真（Vericut / 宇龙）→ 机床空运行（锁住、图形模拟）→ 首件试切。**仿真过了不等于能切，仿真软件不认你的实际刀杆和卡爪。**

## 7. 建议的落地形态

| 不做 | 要做 |
|---|---|
| LLM 直接输出 `.nc` 给车间 | LLM 输出 `.nc` **草稿** + 结构化参数 JSON |
| 靠人肉眼找错 | 规则引擎跑几何自洽性（本例 `03_toolpath.py` 只是雏形，可扩成完整校验器） |
| 靠「模型很强」说服客户 | 每一次生成都附 **刀路图 + 关键尺寸核对表 + 风险提示**，让人 3 分钟能看完 |
| 一步到位替代工艺员 | 先把「阶梯轴/法兰盘/轴套」这类回转体做成模板库，覆盖 60%，剩下的明确说不在范围内 |

**商业上真正的卖点不是「自动编程」，是「把工艺员的重复劳动压掉 70%，同时把不一致性压到 0」。** 客户买的是「不再因为老师傅凭感觉写程序而废件」。

## 8. 本 PoC 的已知边界

- 只覆盖**两轴车削回转体**，不涉及铣削、多轴、车铣复合。
- 不处理**热处理变形、让刀、振纹** —— 这些靠参数和经验，代码解决不了。
- 公差只做**尺寸标注**，没有做公差链分析与补偿量计算（真做要接入实测反补，是另一个工程）。
- 未做**碰撞几何校验**（刀杆/刀塔/卡爪），这一层建议直接买 Vericut 或宇龙，自己写不划算。
